# 组会论文汇报 PPT 制作 Skill

一套面向中文组会论文汇报的制作指南与 Python 页面模板，主要适用于流程挖掘、神经符号学习、预测性流程监控等方向。

本项目从 3 份组会汇报 PPT（66–73 页）及多轮修改中整理而来，包含章节组织、页面样式、方法讲解、图表处理和演讲者备注的写法。可以手动编辑模板，也可以通过 Python 脚本生成页面。

> 本项目提供制作规范与页面生成函数，不会自动读取论文并生成完整汇报。论文解读、内容取舍和最终排版仍需由使用者或 AI 助手完成。

## 1. 文件说明

| 文件 | 作用 | 何时使用 |
|------|------|----------|
| [SKILL.md](SKILL.md) | 详细制作规范，包含章节结构、配色、字体、流程图、备注和检查清单 | 规划汇报内容或让 AI 助手按规范制作时 |

| `demo_output.pptx` | 运行脚本后生成的 17 页演示文件，当前目录不预置此文件 | 查看脚本提供的页面样式时 |
| [README.md](README.md) | 项目介绍与快速上手说明 | 首次使用时 |

## 2. 选择使用方式

### 方式 A：手动编辑模板

适合主要在 PowerPoint / WPS 中制作、希望直接调整版式的使用者。

1. 复制 `模板.pptx`，以论文名另存为新文件，保留原模板。
2. 替换封面、背景、相关工作、方法、实验和结论等内容。
3. 按需复制内容页，删除不需要的示例页和重复章节页。
4. 补充演讲者备注，检查章节编号和前后衔接。
5. 放映检查或导出 PDF，逐页确认文字、图片和公式是否清晰。

**注意：模板不是完全空白文件。** 使用前应清理旧标题、日期、示例文字和备注，并检查水印、章节编号及其他模板残留。

### 方式 B：通过 Python 生成

适合需要批量生成页面、统一样式，或希望由代码组织内容的使用者。

#### 第一步：安装依赖

```bash
python -m pip install python-pptx
```

脚本使用 Noto Sans SC、微软雅黑、Arial 等字体。缺少对应字体时，PowerPoint / WPS 可能替换字体，影响换行和布局。

#### 第二步：生成演示文件

在项目目录中运行：

```bash
python ppt_template.py
```

脚本会在**当前工作目录**生成 `demo_output.pptx`，共 17 页，用于展示封面、内容页、相关工作、模块导览、公式、对比表格和结尾等样式。它不是一份内容完整的论文汇报；重复运行会覆盖同名文件。

#### 第三步：创建自己的汇报脚本

在 `ppt_template.py` 同级目录新建 `make_ppt.py`，显式导入需要的函数：

```python
from ppt_template import (
    create_presentation,
    add_cover_page,
    add_background_page,
    add_section_divider,
    add_content_page,
    add_ending_page,
)

prs = create_presentation()

add_cover_page(
    prs,
    cn_title="论文中文标题",
    en_title="English Paper Title",
    university="学校或单位",
    presenter="汇报人",
    date_str="2026-11-10",
)

add_background_page(
    prs,
    background_text="说明研究任务、现有方法及尚未解决的问题。",
    innovation_text="1. 核心改进一\n2. 核心改进二",
    notes_text="用口语说明这个问题为什么值得研究，再引出论文的改进。",
)

add_section_divider(prs, 1, "方法")

add_content_page(
    prs,
    title_text="方法总体思路",
    body_text="输入是什么\n经过哪些处理\n最终输出什么",
    notes_text="先解释输入和输出，再按顺序讲清各模块的作用。",
)

add_content_page(
    prs,
    title_text="结论与局限",
    body_text="主要贡献\n实验支持的结论\n适用条件与局限",
    notes_text="区分论文已验证的结果、作者解释和后续研究设想。",
)

add_ending_page(prs, text="谢谢大家")

prs.save("output.pptx")
```

运行：

```bash
python make_ppt.py
```

生成的 `output.pptx` 可继续在 PowerPoint / WPS 中编辑。也可以复制原脚本并修改其中的 `demo()`，但建议保留原脚本作为可复用的函数库。

**当前实现说明：** `create_presentation()` 创建新的 16:9 演示文稿，各页面函数通过代码添加装饰，并不读取 `模板.pptx`。虽然函数签名保留了 `template_path` 参数，当前实现未使用它；需要直接修改模板时，请使用方式 A。

### 方式 C：配合 AI 助手使用

向 AI 助手提供 `SKILL.md`、论文全文、模板文件，以及汇报时长、听众基础和输出要求。可参考以下请求：

```text
请参考 SKILL.md 和模板.pptx，为所附论文制作中文组会汇报 PPT。
汇报时长为 30 分钟，听众了解流程挖掘基础。
先梳理研究问题、核心方法和实验依据，再确定逐页大纲。
每页提供适合口头讲解的备注；教学示例需明确标注，
不要把构造的数字当作论文结果。保留原模板，另存为新文件。
```

是否能直接产出 PPTX，取决于所用 AI 助手是否具备本地文件读写和脚本执行能力。

## 3. 页面函数速查

以下函数均位于 `ppt_template.py`，具体参数和调用方式可查看函数定义及 `demo()`。

| 页面用途 | 函数 |
|----------|------|
| 封面 / 结尾 | `add_cover_page` / `add_ending_page` |
| 问题背景与创新点 | `add_background_page` |
| 章节分隔 / 通用内容 | `add_section_divider` / `add_content_page` |
| 单篇文献介绍 | `add_literature_page` |
| 相关工作分类 / 分类总结 | `add_related_work_page` / `add_related_work_summary` |
| 模块导览 / 编号子节 | `add_module_overview_page` / `add_subsection_page` |
| 图片与说明 | `add_image_content_page` |
| 公式与符号解释 | `add_formula_page` |
| 多维度表格对比 | `add_comparison_table` |
| 两篇论文对比 | `add_paper_comparison_page` |

自定义页面可组合使用 `add_page_decorations`、`add_title_bar`、`add_info_block`、`add_label_button` 和 `add_connector`；演讲者备注可通过 `add_notes` 单独添加。

## 4. 制作规范速查

### 内容组织

推荐主线：

```text
封面 → 问题背景 → 引言 → 相关工作 → 方法 → 实验 → 结论 → 结尾
```

方法部分按四个阶段展开：

| 阶段 | 要回答的问题 |
|------|--------------|
| 基础知识 | 任务是什么？以往怎么做？问题在哪里？ |
| 方法框架 | 输入、模块和输出如何连接？ |
| 详细讲解 | 每个模块怎么工作？公式、例子和改进点是什么？ |
| 方法总结 | 一个完整案例如何走完流程？ |

`SKILL.md` 提供了精简版 30–40 页、完整版 60–73 页等组织参考。页数、文献数量和备注长度应结合汇报时长与论文内容确定，不应仅为达到数量而扩充。

### 视觉样式

| 项目 | 默认设置 |
|------|----------|
| 页面比例 | 16:9，约 13.33 × 7.50 英寸 |
| 主色 | 深蓝 `#122E66`，用于标题与主要装饰 |
| 强调色 | 红色 `#FF0000`、橙色 `#E67E22`，用于少量重点 |
| 正文颜色 | 深灰 `#333333` |
| 页面与信息块背景 | 白色为主，辅以浅蓝、浅橙、浅绿 |
| 中文正文 | Noto Sans SC，通常 16–18 pt |
| 中文标题 | 微软雅黑，封面与普通内容页分别设置字号 |
| 英文 | Arial；部分学术内容可用 Times New Roman |
| 章节大数字 | Impact，166 pt |

### 演讲者备注

备注是口头讲稿，不是页面文字的重复。推荐按以下顺序组织：

```text
目的：这页要说明什么，为什么现在讲。
讲解：解释原理、因果、例子和关键数字。
衔接：说明与下一页或下一模块的关系。
```

- 语气自然，像向老师和同学讲解；术语首次出现时给出英文名称和白话解释。
- 一般内容页可参考 150–450 字；封面、章节页、结尾页不必套用同一长度。
- 讲解过长时优先精简或拆页，不靠缩小字号容纳。
- 明确区分论文结果、教学示例和个人推测。

### 图表与公式

- **方法流程图与架构图**：按规范重绘为中文，保持原有模块关系和方法含义。
- **实验结果图表**：优先保留论文原图，完整保留坐标轴、图例、单位和必要注释，并标明来源。
- **框架回指**：复用同一框架，标出当前模块，避免反复绘制不同版本。
- **图片**：插入后检查宽高比和清晰度；当前图片函数可能同时指定宽高，需要按原图比例调整。
- **公式**：`add_formula_page` 使用文本形式的数学符号，不会自动解析 LaTeX。复杂公式可先渲染为图片，或在 PowerPoint / WPS 中手动插入。

## 5. 交付前检查

- [ ] 已替换模板旧内容，清理无关备注、水印、重复页面和错误编号。
- [ ] 每页有明确重点，方法讲解与贯穿案例能够前后衔接。
- [ ] 数据、公式和结论可回查论文，教学示例已单独标注。
- [ ] 相关工作有分类与总结，不是逐篇罗列。
- [ ] 图表在放映尺寸下可读，没有变形、裁切或缺失图例。
- [ ] 字体、颜色、标题位置和子节编号保持一致。
- [ ] 文字、形状、连线和图片没有遮挡或溢出。
- [ ] 备注适合口头讲解，内容页之间有自然衔接。
- [ ] 已实际打开 PPTX，并通过放映或导出 PDF 逐页检查。

脚本成功运行只代表文件已生成，不代表内容与视觉质量已经通过检查。

## 6. 详细规范与来源
